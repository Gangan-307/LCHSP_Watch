# LVGL 硬件桥接章节融合设计

## 目标

将用户提供的“LVGL 与硬件外设的桥接控制（开关灯实战）”内容融合到现有 `LVGL知识清单及注意事项.md` 中，使其成为现有学习资料的一部分，并保持整份文档的系统性、可检索性和面试复盘价值。

## 设计原则

- 不删除现有文档中的有效内容。
- 不修改原有知识结论的含义，只做结构性融合与表达优化。
- 新增内容必须与现有章节逻辑衔接自然，避免像“外插附件”。
- 新增内容必须保留“实战桥接”属性，突出 UI 事件到硬件驱动调用的完整链路。
- 在用户原始内容基础上，允许补充少量工程化注意事项，但不扩展为无关主题。

## 融合位置

采用“独立新章”方案：

- 现有“四、RT-Thread/SiFli 集成要点”之后插入新主章节。
- 现有“五、调试问题库”及后续章节顺延编号。

新的主线结构将变为：

1. 使用建议与快速定位

## 内容处理规则

- 保留用户原文中的主示例：`on_led_toggle`、`ui_events.c`、`rt_device_find()`、`rt_device_control()`、`rt_kprintf()` 等核心桥接链路。
- 对原文做文档化重写，使其与现有文档语言风格统一。
- 保留“不要在 UI 回调中写死循环”的重点警示，并强化其与 `lv_timer_handler()` 卡死之间的因果关系。
- 保留“中断中不要直接调用 LVGL API”的规则。
- 保留“Keep custom code” 和 “Device Not Found” 相关检查项。

## 新增但不越界的注意事项

允许补充以下工程化注意事项：

- `rgb_dev == RT_NULL` 时必须先做空指针保护。
- 回调函数要“快进快出”，耗时动作应转交工作线程。
- 如果需要闪烁、渐变、延时动作，建议通过线程、定时器或消息机制处理，而不是阻塞 UI 回调。
- UI 控件文本更新与硬件状态更新应尽量保持一致，避免“灯已亮但 UI 仍显示 OFF”。
- 重新导出 SquareLine 代码前，应确认自定义代码不会被覆盖。
